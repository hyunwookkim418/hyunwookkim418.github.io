Unmanaged Access Points Causing Wireless Interference and Production Count Issues

February 6, 2026
Network · Wireless · RF Interference · Aruba · OT

Overview

A Point of Production (POP) system was experiencing intermittent production count discrepancies and communication delays in a localized area of the factory floor.

The POP system collected production counts over the wireless network, so the initial troubleshooting process included both the production system and the wireless infrastructure.

PLC logic and POP application behavior were confirmed to be operating normally, which narrowed the investigation to the wireless communication path.

Root Cause A legacy access point from a previous deployment was still powered on and broadcasting the same SSID. A nearby consumer-grade wireless router was also operating in the area. These unmanaged devices degraded the local RF environment and caused unstable wireless connectivity.

Why It Matters

Wireless problems in industrial environments do not always result in a complete communication failure.

Partial RF degradation can reduce throughput and connection stability while devices remain technically connected to the network.

In this case, degraded wireless communication contributed to delayed or inconsistent production data.

This type of issue can be difficult to detect because the system may continue operating while real-time information becomes delayed or incomplete.

Environment

  • Access Point: Hewlett-Packard Aruba AP-535
  • Wireless: 802.11ax, 2.4 GHz / 5 GHz
  • Management: Local Aruba Virtual Controller
  • Environment: Industrial production floor
  • Issue Type: RF interference / unmanaged wireless devices
  • Impact: Unstable connectivity and delayed production count communication

Troubleshooting Process

1. Verify the Problem On-Site

The affected production area was inspected while monitoring wireless client status through the Aruba Virtual Controller.

The affected client showed extremely low throughput and unstable wireless connectivity.

2. Verify the Application and Control System

PLC logic and POP application behavior were reviewed and confirmed to be operating normally.

This helped rule out the production application and control logic as the primary source of the issue.

3. Inspect the Local Wireless Environment

A physical inspection of the surrounding production area was performed to identify possible sources of interference.

During the inspection, a legacy access point from a previous deployment was discovered.

The device was still powered on and broadcasting the same SSID as the production wireless network.

4. Identify Additional Unmanaged Wireless Devices

A nearby consumer-grade home router was also found operating in the same area.

The combination of multiple unmanaged wireless devices further degraded the local RF environment and contributed to unstable client connectivity.

Resolution

The legacy access point and consumer-grade wireless router were powered off and removed from the production area.

Wireless stability improved immediately after the unmanaged devices were removed.

Normal communication was restored, resolving the production count delays associated with the degraded wireless connection.

Lessons Learned

  • Undocumented or temporary wireless devices can become hidden sources of RF interference.
  • Physical inspection remains an important part of wireless troubleshooting, especially in industrial environments.
  • A wireless client can remain connected while experiencing severe degradation in throughput and stability.
  • Application or PLC symptoms should not automatically be treated as application-layer failures when the underlying communication path is unstable.
  • Consumer-grade access points should not be introduced into industrial wireless environments, even temporarily.
